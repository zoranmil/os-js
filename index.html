1. Custom Selects Module
Documentation & Usage Guide

This module converts standard HTML <select> elements into modern dropdown menus with support for live local searching and asynchronous AJAX-driven lookups, while fully preserving selected entries (Select2 UX logic). The module is natively integrated with the reactive OpenShop DOM engine (Two-Way Data Binding).

1. Initialization

Initialization is executed directly via your core OpenShop (OS) DOM library:

// Minimal local mode (search disabled)
            OS('#my-select').Selects();

            // Local mode with real-time DOM-based search enabled
            OS('#categories').Selects({
                issearch: true,
                placeholder: 'Choose category...'
            });
2. Configuration Options
Option Type Default Description and Usage Example
issearch Boolean false Activates the search text input field inside the dropdown menu. If the ajax configuration object is defined, this option is forced to true automatically.
placeholder String 'Choose...' The default text displayed on the main form button before any selection is made. Fully compatible with the local localization wrapper function _P().
searchPlaceholder String 'Search...' The placeholder string visible inside the search input box before typing begins. Automatically localized through _P().
maxHeight String '280px' Defines the maximum height constraint for the dropdown menu panel. If the item count exceeds this value, a vertical scrollbar triggers gracefully (e.g., '400px').
minimumInputLength Integer 0 The minimum character threshold required to fire an AJAX query. If explicitly set to 0, it activates Eager Loading (fetches initial backend results on first click). If set to 2, it waits for a 2-character input.
loadingText String 'Loading...' The notification string rendered alongside a smooth CSS spinner icon while a background network fetch API transaction is actively taking place.
noResultsText String 'No results found' The placeholder text appended to the list view when a search filtering operation (whether local DOM filtering or remote server response data) produces no records.
ajax Object null The asynchronous query parameter configuration object. Maps background lookup behaviors via the embed_url, delay, data, and processResults parameters.
onSelect Function null An optional callback routine triggered immediately when an element choice occurs. Supplies a precise key identifier string, selected array payloads, and raw DOM handle arguments.
3. Advanced Configuration Example (AJAX + Eager Loading + Callback)

The following implementation example handles live records loading from the database instantly upon mouse click (minimumInputLength: 0), customizes backend request structures, and fires an evaluation wrapper routine:

OS("#f_korisnici").Selects({
                placeholder: _P('Select user'),
                searchPlaceholder: _P('Search users...'),
                minimumInputLength: 0, // 0 = Eager Loading (fetches on click), 2 = waits for 2 keyed chars
                maxHeight: '350px', // Larger display boundary container constraints
                onSelect: function(selectedId, nativeSelect) {
                    console.log("Active Selection Payload:", selectedId);
                    // Fire custom internal OpenShop evaluation procedures to re-sync adjacent inputs
                    if (typeof User === 'function') {
                        User();
                    }
                },
                ajax: {
                    embed_url: `${APPL_DIR}${ADMIN_PAGE}/ajax/user_view`,
                    delay: 250, // Anti-hammer debounce delay constraint window in milliseconds
                    data: function(params) {
                        return {
                            op: 'trazi',
                            q: params.term
                        };
                    },
                    processResults: function(data) {
                        // Defensive runtime validation block if the application router serves text instead of object structures
                        if (typeof data === 'string') {
                            try { data = JSON.parse(data); } catch (e) { console.error(e); }
                        }

                        // Format incoming collection maps precisely into plugin requirements: { id, text }
                        var resultsArray = (data.items || []).map(function(userRecord) {
                            return {
                                id: userRecord.id,
                                text: userRecord.first_name || userRecord.text || 'Unnamed Operator'
                            };
                        });

                        return { results: resultsArray };
                    }
                }
            });

2. Custom ImagePreview Modul (AJAX Upload)
Dokumentacija i Uputstvo za Upotrebu

Ovaj modul pretvara standardni <input type="file"> u naprednu zonu za prevlačenje slika (Drag & Drop) sa munjevitim lokalnim pregledom. Ako je u konfiguraciji podešen URL, slika se istog trenutka automatski šalje na server u pozadini preko asinhronog FormData objekta, bez potrebe za osvežavanjem stranice ili ručnim slanjem forme.

1. Inicijalizacija i Pokretanje

Pokretanje vršiš direktno preko tvog OS.fn prototipa uz podršku za asinhroni upload:

// Aktivacija sa automatskim AJAX slanjem na server
                OS('#slika-input').ImagePreview({
                    uploadUrl: '/api/upload-slike.php',
                    uploadData: { folder: 'proizvodi', _token: 'CSRF_123' }, // Dodatni parametri
                    onUploadSuccess: function(response, plugin) {
                        console.log("Server je primio sliku!", response);
                    },
                    onUploadError: function(xhr, status, plugin) {
                        OS.notify.error("Upload nije uspeo!");
                    }
                });
2. Opcije Konfiguracije
Opcija Tip Default Opis
uploadUrl String '' URL tvog API-ja. Ako je prisutan, aktivira se automatski AJAX upload odmah nakon odabira fajla.
uploadData Object {} Dodatni ključ-vrednost parovi koji se šalju uz sliku (npr. ID korisnika, security tokeni).
onUploadSuccess Function null Callback funkcija koja se izvršava nakon uspešnog odgovora servera (HTTP 200).
onUploadError Function null Callback funkcija koja se izvršava ako server vrati grešku ili dođe do prekida veze.
onChange Function null Lokalni callback. Okida se čim browser završi renderovanje slike u preview zoni.
3. API Metode Instance

Preko kreirane instance možeš programski kontrolisati modul:

  • instance.clear() – Potpuno resetuje polje, uklanja sliku i oslobađa memoriju.
  • instance.getBase64() – Vraća Base64 kod slike (korisno za offline čuvanje).
  • instance.getFile() – Vraća sirovi File objekat spreman za manuelnu manipulaciju.
4. Detaljan opis unutrašnjeg mehanizma rada
Hibridni Preview sistem

Modul koristi Blob Object URL za instantni prikaz slike. Za razliku od Base64 formata, Blob ne opterećuje procesor jer kreira direktnu mapu do fajla u RAM memoriji, što omogućava da se slika od 10MB prikaže u milisekundi.

Automatsko oslobađanje RAM-a

Svaki put kada korisnik promeni sliku, modul poziva URL.revokeObjectURL(). Ovo sprečava "curenje" memorije (Memory Leak) koje bi nastalo zadržavanjem starih preview-ova u RAM-u.

Asinhroni FormData proces

Prilikom slanja na server, modul pakuje sliku u FormData objekat. Ovo simulira klasično slanje forme, što znači da vaš backend prima fajl kroz standardni $_FILES niz podataka.

isUploading barijera

Modul poseduje internu zaštitu koja sprečava višestruko slanje istog fajla (Race Condition). Dok traje upload, aktivira se vizuelni overlay koji blokira interakciju dok server ne vrati odgovor.

Funkcionalni tok procesa:
  1. Validacija: Provera MIME tipa fajla. Ako fajl nije slika, proces se obustavlja.
  2. Rendering: Generisanje Blob URL-a i prikaz u .image-preview-render zoni.
  3. Upload: Ako postoji uploadUrl, inicijalizuje se XMLHttpRequest sa FormData paketom.
  4. Feedback: Pozivaju se success/error callback funkcije i osvežava se UI stanje.

4. Core Notify Modul (Dynamic API v2.7.0)
Dokumentacija i Uputstvo za Upotrebu

Globalni sistem obaveštenja integrisan direktno u OS.notify jezgro. Modul se odlikuje Zero-HTML arhitekturom – samostalno generiše i ubacuje potreban Bootstrap šablon u DOM tek pri prvom pozivu, čime eliminiše potrebu za statičkim kodom na stranici.

1. Metode i Pokretanje

Pozivanje se vrši direktno kroz namespace, podržavajući Toasts (brze poruke) i Modale (dijaloge):

// Primena Toast-a (automatsko zatvaranje)
                OS.notify.success('Podaci su sačuvani!', 3000);

                // Primena Modala (zahteva interakciju korisnika)
                OS.notify.confirm2('Da li želite da obrišete stavku?', function() {
                    console.log('Korisnik je potvrdio brisanje');
                }, 'Potvrda akcije');
2. Pregled Dostupnih Metoda
Metoda Tip Opis
success(msg, dur) Toast Zeleno obaveštenje sa auto-hide tajmerom.
error(msg, dur) Toast Crveno obaveštenje za greške u sistemu.
loading(msg) Toast Tamni toast sa spinnerom. Stoji dok se ne pozove hide().
alert(msg, title) Modal Blokirajući dijalog sa tasterom "U redu".
confirm2(msg, cb, title) Modal Dijalog sa potvrdom i callback funkcijom za izvršavanje akcije.
3. Detaljan opis mehanizma rada
Zero-HTML Injection

Funkcija _ensureHtmlExists() proverava prisustvo kontejnera u realnom vremenu. Ako kontejner ne postoji, modul vrši dinamičko ubrizgavanje kompletnog Bootstrap šablona na kraj <body> elementa.

Lifecycle Control

Svaki novi poziv automatski poziva _reset() metodu koja čisti prethodne tajmere (clearTimeout) i uklanja onclick evente, sprečavajući akumulaciju akcija i "pucanje" animacija.

GPU-Accelerated Animations

Prikaz i skrivanje koriste nativne CSS opacity tranzicije. Metoda hide() sačeka tačno 300ms (dužina tranzicije) pre nego što elementu postavi display: none, osiguravajući glatko vizuelno iskustvo.

Smart Callback Sync

Kod confirm2 metode, callback funkcija se izoluje. Tek nakon eksplicitnog klika na "Nastavi", skripta gasi modal i pokreće prosleđenu logiku, čime se sprečava preuranjeno izvršavanje koda.

Tehnički tok procesa:
  1. DOM Init: Provera i kreiranje #os-toast i #os-modal kontejnera.
  2. Cleanup: Resetovanje svih Bootstrap klasa (bg-success, bg-danger, itd.) i skidanje starih slušalaca događaja.
  3. State Management: Postavljanje novog sadržaja, naslova i dodeljivanje callback akcija na tastere.
  4. Execution: Pokretanje CSS tranzicije i aktivacija auto-hide tajmera (samo za Toasts).

7. OPENSHOP GALLERY ENGINE v4.0 UPUSTVO
1. Tehnički preduslovi i zavisnosti (Dependencies)

Za ispravan rad OpenShop Gallery Engine-a, na stranici je obavezno uključiti sledeće skripte pre same inicijalizacije galerije:

  • OS.js Framework (Core) — Glavni pokretač sistema (izložen kao globalni window.OS ili OpenShop). Zadužen je za asinhrono slanje slika na backend preko naprednih asinhronih metoda (OS.post i OS.postJSON), kao i za delegiranje klikova na kantu i kadriranje pomoću OS(selector).on() sistema.
  • Pitagorin Sortable Engine — Dodatak koji se direktno proširuje kroz prototip frameworka i omogućava da pozivom funkcije OS('.hex-grid').Sortable() kontejner dobije Drag & Drop funkcionalnost za promenu mesta slika. Engine automatski detektuje izmenu grida i otključava (omogućava) dugme "Rasporedi" na interfejsu.
  • Inicijalizacija modula: 
      // Pokretanje galerije nakon što je DOM potpuno učitan
  new OSProductGallery({
      productId: window.pid, // ID proizvoda
      valueId: window.sid,   // ID atributa/vrednosti
      ajaxUrl: 'api/gallery_actions.php', // Ruta za upload, krop i brisanje
      orderUrl: 'api/gallery_order.php',   // Ruta za čuvanje redosleda
      imageContainer: '.hex-grid'           // Selektor omotača slika
  });
2. Korisničko uputstvo za upravljanje medijima
  • Dodavanje slika: Klikom na dugme "Odabir slika" birate fajlove sa računara. Sistem pokreće asinhroni Sequential Upload koji obrađuje sliku po sliku. To obezbeđuje maksimalnu stabilnost i sprečava pucanje sesije, dok OS.notify u realnom vremenu rendersuje progress bar za svaki upload.
  • Promena redosleda (Ordering): Uhvatite stavku preko ikonice sa strelicama u gornjem levom uglu i prevucite je na novu poziciju unutar mreže. Nakon premeštanja, dugme "Rasporedi" postaje aktivno. Klikom na njega šalje se indeksirani raspored pozicija u bazu podataka.
  • Kadriranje (High-Res Crop): Klikom na ikonicu makaza otvara se modal. Selektor se na osnovu najnovije optimizacije uvek otvara preko **celog ekrana (od ivice do ivice originala)**, omogućavajući vam da odmah precizno odaberete kadar bez zaostalih starih pozicija.
  • Brisanje slika: Klikom na crvenu kantu pokreće se provera kroz OS.notify.confirm2. Potvrdom akcije element se uklanja iz HTML-a, a fajl briše sa servera.
3. Tehnička specifikacija i JSON struktura

Podaci unutar atributa data-json na svakoj stavci grida su potpuno očišćeni i optimizovani. Izbačen je parametar istorije kadriranja, pa struktura prenosi isključivo sirove podatke o generisanim rezolucijama i veličinama:

{ "original": { "path": "1784569325-3-slider.webp", "width": 570, "height": 680, "size": "3.9 KB" }, "large": { "path": "1784569325-3-slider.webp", "width": 570, "height": 680, "size": "3.9 KB" } }
4. Payload za čuvanje redosleda (Ordering)

Klikom na dugme "Rasporedi" (funkcija saveSortOrder), JavaScript sakuplja sve aktivne ID-jeve iz grida i šalje ih kao čist ravan objekat koji PHP preko standardne application/x-www-form-urlencoded strukture direktno pretvara u asocijativni niz:

{ "op": "ordering", "data[0][id]": "467", "data[0][order]": "0", "data[1][id]": "1784569325", "data[1][order]": "1" }
Zaštitni sloj (Demo mod): Globalna provera za typeof window.DEMO !== 'undefined' ugrađena je u sve ključne funkcije (Upload, Crop, Ordering, Delete) kako bi sprečila bilo kakvo menjanje fajlova ili baze tokom prezentacije.

<div class="form-group mb-3"> <label>Datum rođenja ili opšti datum</label> <input type="text" name="birthday" class="form-control"> <span class="error-poruka" data-for="birthday"></span> <!-- Povezano direktno sa inputom --> </div>

Primenjuje se na napredne UI Kit komponente (Kategorije, Višestruki Tagovi, Boje). Pošto su nativni elementi skriveni, plugin automatski boji crvenu ivicu (border-color) na prvoj pratećoj custom komponenti, a poruka se vezuje ispod njenog kontejnera:

Zahvaljujući ugrađenoj metodi injectStyles(), čim se inicijalizuje validacija, plugin u zaglavlje stranice ubacuje sledeća CSS pravila za automatizaciju prikaza:

3. Ugrađeni sigurnosni i optimizacioni slojevi
AbortController API

Ugrađena zaštita od Race Condition anomalija. Ako korisnik brzo kuca, sistem automatski prekida (abortuje) prethodni AJAX zahtev na mreži pre slanja novog, čime se drastično rasterećuje server.

Event Delegation

Slušaoci za klikove na paginaciju (`.os-page-link`) i sortiranje (`th[data-sort]`) su vezani na krovni kontejner. To znači da klikovi rade bez ponovnog vezivanja čak i kada se ceo HTML unutar tabele kompletno zameni novim odgovorom.

Multi-Instance Safe

Objekat stanja (`state`) i mrežni drajver su enkapsulirani unutar ciklusa petlje svakog elementa. Na istoj stranici možete imati neograničen broj nezavisnih gridova koji se neće međusobno preklapati.

Napomena za bazu podataka: Da bi pretraga radila maksimalno brzo na velikim tabelama proizvoda, obavezno pokrenite kompozitni indeks u SQL-u: ALTER TABLE proizvodi ADD INDEX idx_pretraga (sifra, naziv(100), barkod);
